# Phase 01 - UI Design Contract

> Visual and interaction contract for the Sidebar Grouping Foundation phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none - native macOS SwiftUI contract |
| Preset | not applicable |
| Component library | SwiftUI and AppKit native controls only |
| Icon library | SF Symbols through `Image(systemName:)` and `Label` |
| Font | macOS system font through SwiftUI semantic text styles |

No third-party UI package, shadcn preset, Tailwind configuration, or registry block is used for this phase.

## Visual Hierarchy And Interaction

| Contract | Decision |
|----------|----------|
| Primary surface | Existing left sidebar inside `NavigationSplitView`; keep it compact, native, and source-list-like. |
| Focal point | The grouped source structure first, then the selected job row. Section headers orient scanning; job rows remain the only selectable elements. |
| Header format | Use `{source name} ({visible count})`, for example `launchd (3)` and `Hermes cron (2)`. |
| Header behavior | Source headers are non-selectable, non-collapsible text structure. They do not receive click handlers, selection styling, or keyboard focus. |
| Row behavior | Preserve current job row shape: health dot, one title line, one subtitle line, and existing selected-row background. |
| Subtitle behavior | In grouped rows, remove duplicated source names. Use next-run text when available; otherwise use schedule text. |
| Filtering | Build sections only after search filtering. Header counts and the top sidebar summary both describe visible jobs only. |
| Empty groups | Do not render source headers or placeholder rows for sources with zero visible jobs. |
| Out of scope | No grouping mode picker, custom preferences, collapsible sections, job editing controls, or scanner changes. |

## Spacing Scale

Declared values for Phase 1 additions:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Header-to-row gap, title-to-subtitle gap, compact inline gaps |
| sm | 8px | Sidebar edge padding, header horizontal padding, row horizontal padding |
| md | 16px | Health indicator column width, source section separation, footer/action grouping |
| lg | 24px | Larger split-view or detail spacing only if an existing surrounding container is touched |
| xl | 32px | Reserved for page-level detail spacing outside this phase |
| 2xl | 48px | Reserved for major section breaks outside this phase |
| 3xl | 64px | Reserved for full-page layout spacing outside this phase |

Exceptions: none for Phase 1 additions. Preserve untouched existing row internals where outside the Phase 1 diff, but do not introduce new off-scale spacing.

## Typography

Use only these font sizes and weights for Phase 1 sidebar work:

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Section label | 11px | semibold (600) | 1.2 | Source section headers and visible counts |
| Row title | 13px | regular (400) | 1.35 | Job display names |
| Row detail | 12px | regular (400) | 1.3 | Next-run or schedule subtitles |
| Detail heading | 17px | semibold (600) | 1.2 | Existing detail/support headings only if touched |

Use exactly two weights in this phase: regular (400) and semibold (600). Keep sidebar labels and row text single-line with truncation, not wrapping.

## Color

Use semantic macOS colors and materials so the sidebar adapts to Light Mode, Dark Mode, and user accent color settings.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | macOS regular material; approx. #F5F5F7 light / #1E1E1E dark | Sidebar background and root surface |
| Secondary (30%) | `Color.secondary`; approx. #6E6E73 light / #A1A1A6 dark | Section headers, counts, subtitles, footer metadata |
| Accent (10%) | `Color.accentColor`; selected background at 0.18 opacity | Selected job row background, keyboard focus ring, active sidebar affordance |
| Destructive | system red; approx. #FF3B30 light / #FF453A dark | Not used in Phase 1; reserved for future destructive warnings only |

Accent reserved for: selected job row background, focus indication, and existing system-tinted chrome. Do not use accent color for every interactive element.

Semantic status colors remain separate from accent color:

| Status | Color |
|--------|-------|
| Healthy | system green |
| Waiting | system blue |
| Stale | system orange |
| Failed | system red |
| Unknown | system gray |

Status colors are reserved for the existing `HealthDot` and must not be repurposed as decorative section colors.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Rescan Jobs` if the toolbar action label is touched; Phase 1 adds no new CTA. |
| Section header | `{source name} ({visible count})`, using the visible filtered count. |
| Row subtitle | `{next run text}` when a next run exists; otherwise `{schedule text}`. Do not include source name. |
| Empty state heading | `No matching automations` |
| Empty state body | `Clear the search field or rescan to check launchd and Hermes cron jobs.` |
| Error state | `Could not scan automations. Review the scheduler files, then choose Rescan Jobs.` |
| Destructive confirmation | None. This phase adds no destructive actions and never mutates scheduled jobs. |

## Implementation Contract For Planning

| Area | Contract |
|------|----------|
| Data boundary | Use already-presented `JobPresentation` values. Do not read scheduler files from views. |
| Grouping order | Iterate `JobSource.allCases`: launchd first, Hermes cron second. |
| Row order | Preserve incoming filtered job order inside each source group. Do not sort within groups. |
| Counts | Section counts and top summary count use the visible filtered job list. |
| Selection | Bind selection only to job rows. Headers, summary, and footer remain non-selectable. |
| Testing | Protect grouping behavior with focused validation or equivalent compile-time coverage that respects current SwiftPM target boundaries. |
