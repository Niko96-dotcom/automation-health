<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Contributor local machine -> GitHub issue/PR text | Users may paste local scheduler output, paths, hostnames, job names, screenshots, or secrets into public GitHub fields. |
| GitHub Actions runner -> repository checkout | CI gets a `GITHUB_TOKEN`; workflow permissions must stay least-privilege for build/test. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01-01 | Information Disclosure | Issue templates and PR template | mitigate | Add explicit warnings against raw logs, screenshots, scheduler output, paths, hostnames, job names, tokens, and secrets. |
| T-04-01-02 | Tampering | `.github/workflows/ci.yml` token permissions | mitigate | Preserve top-level `permissions: contents: read`; do not add write permissions. |
| T-04-01-03 | Repudiation | PR verification evidence | mitigate | Require PR checkbox for ``./script/ci.sh`` and privacy scrub completion. |
| T-04-01-04 | Denial of Service | Support expectations | accept | `SUPPORT.md` should set lightweight support boundaries; no service availability promise is created. |
</threat_model>
