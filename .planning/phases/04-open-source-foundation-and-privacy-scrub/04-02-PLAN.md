<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local scheduler files -> public documentation | Docs summarize local scanner behavior without exposing real local automation data. |
| Planned future inventory model -> current public docs | Docs may mention planned confidence/origin work but must not present it as implemented. |
| Scanner core -> SwiftUI app layer | Contributors may accidentally place filesystem IO in views unless docs make the boundary explicit. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-02-01 | Information Disclosure | README/source docs examples | mitigate | Use generic source descriptions and no real job names, hostnames, personal paths, screenshots, or output. |
| T-04-02-02 | Spoofing | Current vs planned feature docs | mitigate | Label future confidence/origin inventory language as planned, not shipped. |
| T-04-02-03 | Tampering | Scanner architecture guidance | mitigate | Direct scanner additions to `ActiveJobsCore` contracts and tests; explicitly forbid view-layer IO. |
| T-04-02-04 | Repudiation | Unsupported source limitations | mitigate | Document best-effort source limits and unsupported sources prominently in README and source docs. |
</threat_model>
