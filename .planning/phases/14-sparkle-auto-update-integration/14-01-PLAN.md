Create `Sources/AutomationHealth/Stores/UpdateStore.swift` — a `@MainActor` `ObservableObject` that wraps Sparkle's `SPUUpdater` and publishes update-related state for SwiftUI views. This is the bridge between Sparkle's imperative/KVO API and SwiftUI's `@Published`/`ObservableObject` model.

**File structure:**

```swift
import Combine
import Foundation
import Sparkle

/// Represents the current state of the Sparkle update cycle.
enum UpdateState: Equatable {
    case idle                          // No update check in progress
    case checking                      // Actively checking for updates
    case updateAvailable(version: String)  // A new version is available
    case upToDate                      // Check completed, no update found
    case error(message: String)        // Sparkle initialization failed or update error occurred
}

@MainActor
final class UpdateStore: ObservableObject {
    // Published state that SwiftUI views observe
    @Published var currentVersion: String = ""
    @Published var canCheckForUpdates: Bool = false
    @Published var updateState: UpdateState = .idle
    @Published var automaticallyChecksForUpdates: Bool = true

    // The underlying Sparkle updater instance
    let updater: SPUUpdater

    /// Initialize with the Sparkle updater. The public key must already be embedded
    /// in the host bundle's Info.plist as SUPublicEDKey — if missing, the updater
    /// will throw on start() and updateState becomes .error.
    init(updater: SPUUpdater) {
        self.updater = updater
        self.currentVersion = Bundle.main.infoDictionary?["CFBundleShortVersionString"] as? String
            ?? Bundle.main.infoDictionary?["CFBundleVersion"] as? String
            ?? "Unknown"
        self.automaticallyChecksForUpdates = updater.automaticallyChecksForUpdates
        self.canCheckForUpdates = updater.canCheckForUpdates
    }

    /// Start the updater and begin observing KVO properties.
    func startUpdater() {
        do {
            try updater.start()
        } catch {
            updateState = .error(message: error.localizedDescription)
            return
        }

        // Observe Sparkle KVO properties and bridge to @Published
        updater.publisher(for: \.canCheckForUpdates)
            .receive(on: DispatchQueue.main)
            .assign(to: &$canCheckForUpdates)

        updater.publisher(for: \.sessionInProgress)
            .receive(on: DispatchQueue.main)
            .sink { [weak self] inProgress in
                if inProgress {
                    self?.updateState = .checking
                }
            }
            .store(in: &cancellables)
    }

    /// User-initiated manual update check.
    func checkForUpdates() {
        updater.checkForUpdates()
    }

    /// Toggle automatic background checks.
    func setAutomaticallyChecksForUpdates(_ enabled: Bool) {
        automaticallyChecksForUpdates = enabled
        updater.automaticallyChecksForUpdates = enabled
    }

    // MARK: - Private

    private var cancellables = Set<AnyCancellable>()
}
```

**Design decisions (per Context-14 Claude's Discretion):**

1. **UpdateState enum** — Four cases: `.idle`, `.checking`, `.updateAvailable(version:)`, `.upToDate`, `.error(message:)`. This satisfies the UI Spec's three visual states (Normal, Checking, Error) plus `.updateAvailable` for future use by plan 14-02.

2. **KVO bridging** — `canCheckForUpdates` and `sessionInProgress` are observed via Combine's `publisher(for:)` on NSObject KVO-compliant key paths. `SPUUpdater` is an NSObject subclass with documented KVO compliance for these properties.

3. **Error handling** — If `updater.start()` throws (e.g., EdDSA public key is missing from Info.plist), `updateState` is set to `.error` and the property is published. This matches the UI Spec: "The Updates section must render correctly when Sparkle is not initialized (error state)."

4. **Version fallback** — If `CFBundleShortVersionString` is missing, falls back to `CFBundleVersion`, then to "Unknown". This matches the UI Spec constraint: "must gracefully degrade if Bundle.main CFBundleShortVersionString is missing."

5. **automaticallyChecksForUpdates** — Defaults to `true` (Sparkle default). Initialized from the updater instance (which reads Info.plist `SUEnableAutomaticChecks` if present, otherwise defaults to true). Following Sparkle docs: "developers shouldn't maintain their own set of user defaults on top of SPUUpdater properties" — we read/write through the updater, not UserDefaults directly.

6. **No direct Sparkle delegate conformance by UpdateStore itself** — The updater delegate is handled separately in plan 14-02 (AutomationHealthApp creates it). UpdateStore only observes KVO properties after start().

7. **File location** — `Sources/AutomationHealth/Stores/UpdateStore.swift` follows the established pattern (PreferencesStore.swift, JobStore.swift are at the same location). This file is part of the AutomationHealth executable target which now links Sparkle.

Create `script/generate_sparkle_keys.sh` — a Bash script that downloads the Sparkle 2 release artifacts, extracts the `generate_keys` tool, runs it to produce an EdDSA key pair, and outputs instructions for where to place the keys.

**Key generation model:** Sparkle's `generate_keys` tool produces a private key (stored in the user's login Keychain by default) and prints the public key to stdout. The script wraps this process and also outputs the public key to a file for CI use.

**Script content:**

```bash
#!/usr/bin/env bash
set -euo pipefail

ROOT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
SPARKLE_VERSION="2.9.1"
SPARKLE_ZIP="Sparkle-for-Swift-Package-Manager.zip"
SPARKLE_URL="https://github.com/sparkle-project/Sparkle/releases/download/${SPARKLE_VERSION}/${SPARKLE_ZIP}"
SPARKLE_DL_DIR="$ROOT_DIR/.sparkle-tools"

echo "=== Sparkle EdDSA Key Generator ==="
echo ""

# Step 1: Download Sparkle release if not already cached
if [[ ! -d "$SPARKLE_DL_DIR" ]]; then
  echo "=== Downloading Sparkle ${SPARKLE_VERSION} tools ==="
  mkdir -p "$SPARKLE_DL_DIR"
  curl -fsSL -o "$SPARKLE_DL_DIR/$SPARKLE_ZIP" "$SPARKLE_URL"
  unzip -q -o "$SPARKLE_DL_DIR/$SPARKLE_ZIP" -d "$SPARKLE_DL_DIR"
  echo "Sparkle tools extracted to $SPARKLE_DL_DIR"
else
  echo "Sparkle tools already cached at $SPARKLE_DL_DIR"
fi

# Step 2: Locate generate_keys binary
GENERATE_KEYS="$(find "$SPARKLE_DL_DIR" -name "generate_keys" -type f -perm +111 2>/dev/null | head -1)"
if [[ -z "$GENERATE_KEYS" ]]; then
  echo "Error: Could not find generate_keys binary in Sparkle release." >&2
  echo "Check $SPARKLE_DL_DIR for contents." >&2
  exit 1
fi

echo "=== Running generate_keys ==="
echo ""

# Run generate_keys
PUBLIC_KEY="$("$GENERATE_KEYS" 2>/dev/null)"
GEN_EXIT=$?

if [[ $GEN_EXIT -ne 0 ]]; then
  echo "Error: generate_keys failed with exit code $GEN_EXIT" >&2
  echo "Run manually: $GENERATE_KEYS" >&2
  exit $GEN_EXIT
fi

if [[ -z "$PUBLIC_KEY" ]]; then
  echo "Error: generate_keys produced no output." >&2
  exit 1
fi

echo "=== Key Generation Complete ==="
echo ""
echo "Public key (for Info.plist SUPublicEDKey):"
echo "  $PUBLIC_KEY"
echo ""
echo "The private key has been saved to your login Keychain."
echo ""
echo "=== Next Steps ==="
echo ""
echo "1. Add the public key to the app's Info.plist:"
echo "   <key>SUPublicEDKey</key>"
echo "   <string>$PUBLIC_KEY</string>"
echo ""
echo "2. Export the private key for CI:"
echo "   security find-generic-password -s 'Sparkle Private Key' -w"
echo ""
echo "3. Save the private key as a GitHub Secret: SPARKLE_EDDSA_PRIVATE_KEY"
echo ""
echo "4. Clean up Sparkle tools when done:"
echo "   rm -rf $SPARKLE_DL_DIR"
```

**Script behavior:**
- Downloads Sparkle release ZIP once, caches in `.sparkle-tools/` directory
- Finds and runs `generate_keys` from within the extracted artifacts
- Prints the public key to stdout (for the developer to add to Info.plist)
- Private key is automatically stored in the user's login Keychain by `generate_keys`
- Provides clear next-step instructions
- Follows established pattern: `set -euo pipefail`, `ROOT_DIR` from `BASH_SOURCE`, error messages to stderr

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Sparkle framework -> App binary | Sparkle XCFramework is a binary dependency; its code runs in-process with AutomationHealth |
| Appcast server (GitHub Releases) -> Sparkle updater | The appcast.xml and DMG download are fetched over HTTPS; EdDSA signature verification prevents tampering |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-01 | Tampering | Sparkle XCFramework binary | accept | Binary from official sparkle-project GitHub releases with SPM checksum verification — supply chain risk is inherent to binary dependencies; same risk accepted by all Sparkle consumers |
| T-14-02 | Spoofing | `generate_keys` tool | mitigate | Downloaded from official Sparkle GitHub release with HTTPS; script uses specific version (`2.9.1`) pinned in the URL, not `latest` |
| T-14-03 | Information Disclosure | EdDSA private key in Keychain | mitigate | `generate_keys` stores private key in login Keychain (macOS system-level encryption); script does not print private key to stdout or files; CI export instructions reference `security` CLI which requires Keychain unlock |
| T-14-04 | Elevation of Privilege | Sparkle update installation | mitigate | Sparkle verifies EdDSA signature before installing any update; embedded `SUPublicEDKey` in app bundle cannot be modified without re-signing the app; hardened runtime prevents unauthorized code injection |
| T-14-05 | Denial of Service | Missing EdDSA key | mitigate | UpdateStore.startUpdater() catches thrown error and sets updateState to .error with descriptive message; app continues to function normally without update capability |
</threat_model>
