Sparkle appcast tooling:
- `generate_appcast` tool is in the Sparkle release artifacts (same ZIP as `generate_keys`)
- It scans a directory of archives, signs them with the EdDSA private key, and produces appcast.xml
- The private key is stored in the login Keychain by `generate_keys` and can be exported for CI via `security find-generic-password`
- `sign_update` tool signs individual archives and outputs `sparkle:edSignature="..." length="..."` XML attributes for the `<enclosure>` element
- The `SPARKLE_EDDSA_PRIVATE_KEY` env var holds the base64-encoded private key for CI

Appcast.xml format (for the release script):
```xml
<item>
    <title>Version 2.0</title>
    <sparkle:version>2.0</sparkle:version>
    <sparkle:shortVersionString>2.0</sparkle:shortVersionString>
    <enclosure url="https://github.com/nikomohr/AutomationHealth/releases/download/v2.0/AutomationHealth-2.0.dmg"
               sparkle:edSignature="..."
               length="1234567"
               type="application/octet-stream" />
</item>
```

```bash
echo "=== Step 11: Generate Sparkle appcast ==="

# Only generate appcast for real releases (not dev versions).
if [[ "$VERSION" == "0.0.0-dev" ]]; then
  echo "Skipping appcast generation for dev version ($VERSION)."
elif [ -z "${SPARKLE_EDDSA_PRIVATE_KEY:-}" ]; then
  echo "Warning: SPARKLE_EDDSA_PRIVATE_KEY is not set. Appcast generation skipped." >&2
  echo "Set SPARKLE_EDDSA_PRIVATE_KEY to the base64-encoded EdDSA private key." >&2
  echo "Generate keys: ./script/generate_sparkle_keys.sh" >&2
  echo "Export for CI: security find-generic-password -s 'Sparkle Private Key' -w | base64" >&2
else
  # Locate Sparkle tools from the generate_keys script cache, or try SPM checkout
  SPARKLE_TOOLS_DIR="$ROOT_DIR/.sparkle-tools"
  if [[ ! -d "$SPARKLE_TOOLS_DIR" ]]; then
    SPARKLE_TOOLS_DIR="$ROOT_DIR/.build/checkouts/Sparkle"
  fi

  GENERATE_APPCAST="$(find "$SPARKLE_TOOLS_DIR" -name "generate_appcast" -type f -perm +111 2>/dev/null | head -1)"
  if [[ -z "$GENERATE_APPCAST" ]]; then
    echo "Warning: Could not find generate_appcast tool. Appcast generation skipped." >&2
    echo "Run ./script/generate_sparkle_keys.sh first to cache Sparkle tools." >&2
  else
    # Decode the private key and import to a temporary keychain for signing
    APPCAST_KEYCHAIN="$STAGING/sparkle.keychain"
    APPCAST_KEYCHAIN_PASSWORD="sparkle-appcast-$(date +%s)"

    echo "$SPARKLE_EDDSA_PRIVATE_KEY" | base64 --decode > "$STAGING/sparkle-private-key"

    # Create appcast directory with the current DMG
    APPCAST_DIR="$STAGING/appcast"
    mkdir -p "$APPCAST_DIR"
    cp "$DMG_PATH" "$APPCAST_DIR/"

    # Generate the appcast with EdDSA signing
    # generate_appcast expects the private key in the Keychain or via the
    # SPARKLE_PRIVATE_KEY environment variable, depending on the version.
    # We use the private key file approach with -f flag.
    "$GENERATE_APPCAST" -f "$STAGING/sparkle-private-key" "$APPCAST_DIR" 2>&1 || {
      echo "Warning: generate_appcast failed (see above). Continuing without appcast." >&2
    }

    # If appcast was generated, move it to dist/
    if [[ -f "$APPCAST_DIR/appcast.xml" ]]; then
      cp "$APPCAST_DIR/appcast.xml" "$ROOT_DIR/dist/appcast.xml"
      echo "Appcast generated: dist/appcast.xml"

      # Update the appcast to point to the GitHub Releases URL for this version
      DMG_FILENAME="$(basename "$DMG_PATH")"
      # The DMG will be uploaded to GitHub Releases at:
      # https://github.com/nikomohr/AutomationHealth/releases/download/v{VERSION}/{DMG_FILENAME}
      # Update enclosure URLs in the appcast to point to the final GitHub Releases URL
      sed -i '' "s|file://$APPCAST_DIR/$DMG_FILENAME|https://github.com/nikomohr/AutomationHealth/releases/download/v$VERSION/$DMG_FILENAME|g" \
        "$ROOT_DIR/dist/appcast.xml" 2>/dev/null || true
      echo "Appcast URLs updated to GitHub Releases for v$VERSION"
    fi

    # Clean up sensitive files
    rm -f "$STAGING/sparkle-private-key"
    if [[ -f "$APPCAST_KEYCHAIN" ]]; then
      security delete-keychain "$APPCAST_KEYCHAIN" 2>/dev/null || true
    fi
  fi
fi
```

**Important details:**
- The SPARKLE_EDDSA_PRIVATE_KEY env var contains the base64-encoded EdDSA private key (exported from Keychain via `security find-generic-password -s 'Sparkle Private Key' -w | base64`)
- The `generate_appcast` tool with `-f` flag reads the private key from a file (alternative to reading from Keychain, which is better for CI)
- The appcast.xml paths are rewritten from local `file://` URLs to GitHub Releases download URLs so Sparkle in the app can find the DMG
- Three failure modes are handled: dev version (skip), missing env var (warn), missing tool (warn). None fail the overall release — the DMG is still produced
- Temporary private key file is deleted immediately after use
- `dist/appcast.xml` is the output — this file must be uploaded alongside the DMG in the GitHub Release

## Sparkle Auto-Update Setup

Automation Health uses [Sparkle 2](https://sparkle-project.org) for in-app auto-updates. Each release must be signed with an EdDSA private key so Sparkle can verify the update before installing it.

### Step 1: Generate EdDSA key pair

```bash
./script/generate_sparkle_keys.sh
```

This downloads the Sparkle tools, runs `generate_keys`, and prints a base64-encoded public key. The private key is stored in your login Keychain under the name "Sparkle Private Key".

### Step 2: Embed the public key in the app

Add the public key to the app's `Info.plist` with the key `SUPublicEDKey`. AutomationHealth's `Info.plist` is generated by `script/release.sh` (or `script/build_and_run.sh` for development). Both scripts will need to include this key.

For local development builds (`script/build_and_run.sh`), you can add the key manually after generating it. For release builds, `script/release.sh` reads the key during appcast generation — but the key must also be in the `.app` bundle's `Info.plist` so the running app can verify updates.

Add this to the Info.plist generation in `script/release.sh` (or set it as a constant/script variable):

```xml
<key>SUPublicEDKey</key>
<string>YOUR_PUBLIC_KEY_HERE</string>
```

### Step 3: Export the private key for CI

For CI-based releases (`.github/workflows/release.yml`), the private key must be available as a GitHub Secret:

```bash
# Export the private key from your Keychain (base64-encoded for GitHub Secret)
security find-generic-password -s "Sparkle Private Key" -w | base64
```

Add the output as a GitHub Secret named `SPARKLE_EDDSA_PRIVATE_KEY`.

The release workflow in `.github/workflows/release.yml` passes this secret to `script/release.sh` as the `SPARKLE_EDDSA_PRIVATE_KEY` environment variable.

### Step 4: Add the secret to CI workflow

In `.github/workflows/release.yml`, add a step before the release script runs:

```yaml

This step should be placed after the "Set notarization credentials" step and before the "Build, sign, notarize, and package DMG" step.

### Step 5: Upload appcast.xml with the release

The release script now generates `dist/appcast.xml` during Step 11 (appcast generation). This file must be uploaded alongside the DMG in the GitHub Release.

In `.github/workflows/release.yml`, update the `gh release create` step to include the appcast:

```yaml
- name: Create GitHub Release
  env:
    GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
  run: |
    VERSION="${GITHUB_REF_NAME#v}"
    gh release create "$GITHUB_REF_NAME" \
      --title "Automation Health v$VERSION" \
      --notes "..." \
      --verify-tag \
      "$DMG_PATH" \
      dist/appcast.xml
```

### Key Rotation

If you need to generate a new EdDSA key pair (private key compromised, or regular rotation):

1. Run `./script/generate_sparkle_keys.sh` again — this will overwrite the key in your Keychain
2. Update `SUPublicEDKey` in the app's Info.plist with the new public key
3. Update the `SPARKLE_EDDSA_PRIVATE_KEY` GitHub Secret with the new private key
4. Old versions of the app will continue to work — they will check the appcast signed with the old key, but the new appcast will be signed with the new key. Sparkle supports key rotation via `sparkle:edSignature` and `sparkle:edSignature2` for transition periods.

See [Sparkle's EdDSA migration guide](https://sparkle-project.org/documentation/eddsa-migration/) for detais on rotating signing keys.
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Developer machine -> release artifacts | `generate_appcast` signs appcast.xml locally or in CI — private key access is the trust boundary |
| CI (GitHub Actions) -> release artifacts | EdDSA private key injected via GitHub Secret — GitHub's secret encryption is the trust boundary |
| GitHub Releases -> Sparkle updater (end user) | appcast.xml and DMG served over HTTPS with EdDSA signature verification |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-11 | Information Disclosure | EdDSA private key in CI | mitigate | Private key stored as GitHub Secret (encrypted at rest, masked in logs); decoded from base64 only in the release runner's temporary filesystem; deleted immediately after `generate_appcast` completes |
| T-14-12 | Tampering | appcast.xml generation | mitigate | `generate_appcast` produces EdDSA-signed appcast entries; the private key is only available during the release step; the DMG is already stapled and notarized before appcast generation — appcast references a verified artifact |
| T-14-13 | Repudiation | Release documentation | mitigate | Documentation uses placeholder identifiers only — no real keys, certificates, or credentials are committed to the repository; all copy follows the existing pattern from Phase 13 Plan 03 |
| T-14-14 | Spoofing | `generate_appcast` tool | accept | Tool is downloaded from Sparkle's official GitHub Releases and cached — same trust model as the Sparkle XCFramework (T-14-01); the tool's only output is a signed appcast.xml, which cannot override the already-signed DMG |
| T-14-15 | Denial of Service | Missing SPARKLE_EDDSA_PRIVATE_KEY | mitigate | Release script handles missing env var with a warning (does not fail the release); the DMG is still produced and uploaded; appcast generation is a non-critical step — releases without appcasts still produce functional DMGs |
</threat_model>
