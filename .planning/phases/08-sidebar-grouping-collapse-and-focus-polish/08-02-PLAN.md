<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UI state -> scanner inventory | Grouping/collapse state is local display state and must never mutate scanner records or real automation files. |
| Section headers -> selection | Disclosure headers toggle sections only; job rows remain the only selectable records. |
| Search filter -> collapse state | Search can reveal rows for display, but it must not overwrite the user's in-memory collapsed sections. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Tampering | Sidebar UI | avoid | No edit/run/delete scheduler actions are added; collapse/grouping mutate only `@State` values. |
| T-08-02 | Information Disclosure | SwiftUI views | mitigate | Required grep blocks direct file/process/scanner IO terms in `Sources/AutomationHealth/Views`. |
| T-08-03 | Spoofing | Group labels and subtitles | mitigate | Rows use `JobPresentation` source/confidence/evidence labels and retain source in non-source grouping subtitles. |
| T-08-04 | Repudiation | Collapse and selection | mitigate | Section headers never write `selectedJobID`; collapsing selected rows leaves detail selection unchanged. |
| T-08-05 | Denial of Service | Keyboard navigation | mitigate | Navigation flattens visible section jobs only and returns nil for empty visible results. |
| T-08-06 | Information Disclosure | Preference state | avoid | Plan uses in-memory `@State` only and avoids `UserDefaults`, `@AppStorage`, JSON, or file persistence. |
</threat_model>
