# Phase 08 - UI Design Contract

> Visual and interaction contract for sidebar grouping, collapsible sections, visible-row keyboard navigation, and accessible focus polish. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase Boundary

Phase 8 turns the existing source-grouped sidebar into a richer native navigation surface while preserving the read-only automation inventory model.

In scope:

- Add sidebar grouping modes for `Source`, `Origin`, `Health`, `Trigger`, and `Confidence`.
- Default grouping to `Source` to preserve the current shipped sidebar behavior.
- Add collapsible section headers with counts and disclosure affordances.
- Keep selected detail coherent when the selected row is hidden by collapse or search.
- Make keyboard Up/Down navigation operate over visible job rows only.
- Temporarily reveal matching rows during search without mutating stored collapse state.
- Replace the oversized default blue sidebar focus rectangle with a restrained accessible focus cue.

Out of scope:

- Persisting grouping or collapsed-section state. Future `PREF-01` owns persistence.
- Scanner IO, filesystem reads, process calls, script-content analysis, or scheduler mutation in SwiftUI views.
- Adding, editing, running, repairing, deleting, or rewriting real automation jobs.
- New third-party packages or a broad design-system redesign.
- Large cards, decorative sidebar treatments, oversized headers, or marketing-style layout.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | Native SwiftUI/AppKit only |
| Icon library | SF Symbols |
| Font | macOS system font, SF Pro |

Design system notes:

- No React, Tailwind, shadcn, web registry, or third-party component system is present.
- Use existing SwiftUI surfaces and controls: `NavigationSplitView`, `.searchable`, `ScrollView`, `LazyVStack`, `Menu` or compact `Picker`, plain `Button`, `ProgressView`, and native focus APIs.
- Use AppKit interop only if SwiftUI cannot suppress or replace the default focus rectangle cleanly.
- Keep sidebar row corner radii at 6px and detail/card radii at 8px or less.
- Icon-only controls must have `.help` text and accessibility labels. Section disclosure controls may be icon-plus-title rows, not unlabeled glyphs.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Disclosure icon gaps, inline label/count gaps, divider spacing |
| sm | 8px | Sidebar row padding, section header padding, control gaps |
| md | 16px | Sidebar header groups, search-empty text rhythm, footer groups |
| lg | 24px | Filtered empty-state vertical padding |
| xl | 32px | Reserved for rare sidebar empty-state breathing room |
| 2xl | 48px | Not used in normal sidebar grouping UI |
| 3xl | 64px | Not used in Phase 8 |

Exceptions: Native macOS control intrinsic sizes, SF Symbol drawing metrics, and 1-2px focus/outline strokes are platform and accessibility metrics rather than spacing tokens.

Implementation constraints:

- Preserve stable 38px minimum sidebar row height unless the existing row content genuinely wraps.
- Section headers must not shift row positions on hover or focus.
- Search-revealed sections should reuse the same spacing as normal expanded sections.
- The custom focus cue may use a 1px or 2px inset stroke; do not create a thick filled focus panel.

## Typography

Use exactly these type roles for Phase 8 UI additions:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 600 | 1.3 |
| Body | 14px | 400 | 1.5 |
| Heading | 18px | 600 | 1.25 |
| Display | 24px | 600 | 1.2 |

Typography constraints:

- Allowed weights: 400 regular and 600 semibold only.
- Sidebar rows, section headers, counts, grouping control labels, and help-adjacent microcopy use Label and Body roles only.
- Display-scale type remains limited to existing detail headers; Phase 8 must not introduce display-scale sidebar text.
- Counts use monospaced digits where possible.
- Long job names and subtitles remain one line with truncation in the sidebar.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F5F5F2` light / `#1D1D1F` dark | Window background and broad native surfaces |
| Secondary (30%) | `#E8E8E3` light / `#2A2A2D` dark | Sidebar material, section header surfaces, footer, subtle hover states |
| Accent (10%) | `#32D583` | Selected sidebar row, active grouping checkmark/tint, custom keyboard focus cue, existing app health pulse identity |
| Destructive | `#D92D20` | Destructive actions only; Phase 8 adds no destructive actions |

Accent reserved for: selected sidebar row treatment, active grouping indicator, custom focus stroke, and existing app health pulse identity. Do not use accent for every sidebar row, every section header, broad backgrounds, section counts, or Candidate/Manual evidence labels.

Color constraints:

- Existing semantic health colors remain unchanged: green for alive, blue for waiting, orange for stale, red for needs attention, and gray for unknown.
- Origin, trigger, and confidence groups must rely on text labels and deterministic placement, not new decorative palettes.
- The focus cue must remain visible in light mode, dark mode, active window, inactive window, and high-contrast contexts. Use shape/stroke in addition to color.

## Visual Hierarchy

Primary focal point:

- Sidebar: the selected job row remains the primary anchor. Grouping controls and disclosure headers are supporting navigation controls, not the main visual target.

Secondary focal points:

- Active grouping mode in the compact sidebar-local control.
- Expanded/collapsed section headers with counts.
- Custom focus cue when the sidebar list has keyboard focus.
- Filtered empty state when search returns no visible records.

Icon mapping:

| Element | SF Symbol | Treatment |
|---------|-----------|-----------|
| Grouping control | `line.3.horizontal.decrease.circle` or native picker affordance | Compact sidebar-local control with label/help |
| Expanded section | `chevron.down` | Plain disclosure affordance before section title |
| Collapsed section | `chevron.right` | Plain disclosure affordance before section title |
| Focus cue | none required | Shape/stroke cue, not a decorative icon |

Visual constraints:

- Section headers are interactive disclosure rows or contain disclosure buttons, but they are never selectable jobs.
- The selected row fill and keyboard focus cue must be visually distinct. Selection can use the existing compact accent fill; focus uses an outline or inset stroke.
- No explanatory paragraphs should appear in the sidebar. Use concise `.help` text for origin/source distinction where needed.

## Layout Contract

### Sidebar Header And Grouping Control

Place a compact grouping control in or immediately beside the existing sidebar header. The control must be local to the sidebar, not placed in the global toolbar.

| Control | Label | Options | Default |
|---------|-------|---------|---------|
| Grouping menu or compact picker | Group Sidebar By | Source, Origin, Health, Trigger, Confidence | Source |

Control behavior:

- The selected grouping mode must be visible through menu checkmark state, picker selection, or adjacent compact label.
- The control uses exact option labels: `Source`, `Origin`, `Health`, `Trigger`, `Confidence`.
- Help text for `Origin`: "Origin groups ownership or authorship. Source is the scheduler or inventory adapter."
- Do not persist the selected grouping mode in Phase 8.

### Section Headers

Section headers use one compact row:

- Disclosure affordance.
- Section title.
- Filtered visible count.
- Optional concise help text on origin/source distinction.

Section header behavior:

- Clicking a section header toggles collapse/expand.
- Headers must use `.buttonStyle(.plain)` or equivalent native restraint.
- Headers must expose accessibility labels such as "Collapse Source section launchd, 8 records" or "Expand Origin section User-authored, 3 records".
- Headers must not write to `selectedJobID`.

### Group Ordering

All grouping modes use deterministic domain order:

| Mode | Order |
|------|-------|
| Source | `launchd`, `Hermes cron`, `cron`, `Shortcuts`, `Automator`, `Candidate scripts`, `Manual records` |
| Origin | `User-authored`, `Third-party app`, `System`, `Unknown` |
| Health | `Needs attention`, `Stale`, `Waiting`, `Alive`, `Unknown` |
| Trigger | `Time-based`, `Login / Keep Alive`, `File / Queue Trigger`, `Registered Only`, `Candidate Scripts`, `Manual / Unspecified` |
| Confidence | `Scheduled`, `Registered`, `Candidate`, `Manual` |

Ordering constraints:

- Do not alphabetize these groups.
- Empty groups are omitted.
- Refreshes must preserve stable section identity and avoid visually reshuffling unrelated rows.

### Sidebar Rows

Primary line: `displayName`, one line, primary color.

Secondary line by grouping mode:

| Grouping Mode | Subtitle Pattern |
|---------------|------------------|
| Source | `{Confidence} - {schedule or next run}` |
| Origin | `{Source} - {Confidence} - {schedule or next run}` |
| Health | `{Source} - {Confidence} - {schedule or next run}` |
| Trigger | `{Source} - {Confidence} - {schedule or next run}` |
| Confidence | `{Source} - {schedule or next run}` |

Row behavior:

- Job rows remain the only selectable items in the sidebar.
- Candidate and Manual records keep their Phase 7 evidence wording and must not look like proven scheduled jobs unless their confidence says so.
- Launchd rows in `Origin` grouping split by `JobOrigin` while retaining scheduler source in the row subtitle.

### Collapse, Search, And Selection

Collapse state contract:

- Store collapse state in memory only.
- Key collapse state by grouping mode and section identity.
- All sections are expanded the first time a grouping mode is visited.
- Switching grouping modes preserves in-memory collapse state per mode for the current app session.

Search behavior:

- Search filters jobs using existing `JobPresentation.searchText`.
- Search temporarily reveals matching rows inside matching groups, even if those groups were previously collapsed.
- Searching must not mutate stored collapse state.
- Clearing search restores the previous collapsed/expanded state.
- Section counts under search reflect filtered visible result count.
- Filtered empty state remains non-selectable.

Selection behavior:

- Collapsing a section containing the selected job does not clear or move `selectedJobID`.
- Detail view continues showing the selected job until the user selects another visible job or the store loses that job after refresh.
- Search filtering does not silently select a different record.

### Keyboard And Focus Behavior

Keyboard navigation:

- Up/Down moves across visible job rows only after grouping, collapse, and search filtering are applied.
- Hidden collapsed rows and search-hidden rows are skipped.
- If the current selection is hidden, Down moves to the next visible row after the hidden record or its section boundary when positional context is available; Up moves to the previous visible row before it.
- If no rows are visible, navigation returns nil and the empty state remains non-selectable.

Focus styling:

- Keep the sidebar list keyboard focusable.
- Replace the oversized default blue rectangle with a custom focus cue that matches the existing dark sidebar/search treatment.
- Preferred cue: 1-2px rounded inset stroke around the focused list surface or focused selected row.
- Focus cue must remain visible in active, inactive, dark, light, and high-contrast contexts.
- Do not remove focus visibility to hide the default rectangle.

Additional copy constraints:

- Use "automation records" rather than "jobs" in user-facing empty states when describing the whole inventory.
- Do not add explanatory sidebar paragraphs for grouping. Prefer `.help` text and accessibility labels.
- Trigger group labels must be conservative evidence labels and must not claim registered, candidate, or manual records are scheduled.

## Implementation Contract

Presentation helpers:

- Add grouping, trigger classification, section identity, collapse-state, row-subtitle, and visible-navigation helpers in `Sources/AutomationHealth/Models/JobPresentation.swift` or a neighboring presentation model file.
- Use only `JobPresentation` and normalized `ScheduledJob` fields. Do not perform scanner IO in presentation helpers.
- Trigger classification is presentation-only and conservative.

Trigger classification priority:

1. Candidate confidence or Candidate scripts source -> `Candidate Scripts`.
2. Manual confidence or Manual records source -> `Manual / Unspecified`.
3. Registered confidence without direct schedule evidence -> `Registered Only`.
4. Existing schedule text indicating watch, watched files, queue, or files queued -> `File / Queue Trigger`.
5. Existing schedule text indicating login, keep alive, `RunAtLoad`, or stays running -> `Login / Keep Alive`.
6. Existing direct schedule evidence such as `nextRun`, cron expression, `@hourly`-style cron token, clock time, `Daily`, `Every`, `Monthly`, or weekday wording -> `Time-based`.
7. Fallback -> `Manual / Unspecified`.

View integration:

- `ContentView` may own `@State` for grouping mode and in-memory collapse state.
- `SidebarView` renders grouped sections, disclosure headers, visible counts, keyboard navigation, and custom focus styling.
- SwiftUI views must not read scheduler files, script files, manual JSON, output files, source directories, shell history, or process output directly.

## Validation Contract

Required self-test coverage:

- Grouping mode labels are exactly `Source`, `Origin`, `Health`, `Trigger`, and `Confidence`.
- Source, origin, health, trigger, and confidence sections follow the deterministic orders in this UI-SPEC.
- Launchd records with different origins split into different `Origin` groups while row subtitles still show source.
- Trigger classification does not classify registered Shortcuts or Automator records as scheduled without direct schedule evidence.
- Collapsed sections hide rows from visible navigation without clearing selected job IDs.
- Search reveals matching rows without mutating stored collapse state.
- Keyboard navigation skips collapsed and search-hidden rows and handles hidden selected IDs predictably.

Required commands:

- `./script/test.sh`
- `./script/ci.sh`
- View-layer IO grep:
  `! rg -n "Data\\(contentsOf:|FileManager\\.default|contentsOfDirectory|JSONEncoder|JSONDecoder|crontab|shortcuts list|launchctl" Sources/AutomationHealth/Views`

Required manual verification:

- Switch through all grouping modes and confirm order, counts, labels, and row subtitles.
- Collapse/expand sections and confirm selected detail remains coherent.
- Collapse a section, search for a matching row inside it, confirm the row appears, clear search, and confirm prior collapse state returns.
- Use Up/Down while sections are collapsed and while search is active; confirm selection moves only to visible rows.
- Verify the default blue focus rectangle is gone and the custom focus cue remains visible in dark mode, light mode, inactive window state, and high-contrast mode where practical.
