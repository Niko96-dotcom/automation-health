<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Committed source PNG -> generated icon assets | Local scripts transform source art into multiple committed PNG sizes and an `.icns` resource. |
| Repository assets -> generated app bundle | `script/build_and_run.sh` copies the committed `.icns` into `dist/AutomationHealth.app/Contents/Resources`. |
| Developer docs -> maintainer regeneration workflow | Docs must describe local deterministic regeneration without secrets, network requirements, signing, or notarization claims. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-02-01 | Tampering | `script/generate_app_icon.sh` | mitigate | Use explicit source and output paths, fail on missing/non-square source PNG, and use built-in `sips` and `iconutil` only. |
| T-05-02-02 | Denial of Service | Local bundle build | mitigate | Regenerate the icon only when `.icns`, source PNG, or script timestamps require it; fail with the generator's clear missing-source error. |
| T-05-02-03 | Information Disclosure | Generated assets and docs | mitigate | Use only selected abstract source art from Plan 05-01 and document no screenshots, private data, local paths, terminal output, or real scheduler details. |
| T-05-02-04 | Spoofing | App bundle identity | mitigate | Copy `AutomationHealth.icns` into `Contents/Resources` and declare `CFBundleIconFile` so the local app presents the intended identity. |
| T-05-02-05 | Elevation of Privilege | Regeneration workflow | avoid | Do not introduce secrets, API keys, network calls, installers, signing, notarization, or new executable dependencies beyond built-in macOS tools. |
</threat_model>
