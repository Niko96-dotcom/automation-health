<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User script directories -> candidate scanner | File metadata and paths are treated as untrusted local input and never executed. |
| Candidate scanner -> inventory model | File presence becomes Candidate confidence only, not schedule evidence. |
| Missing/unreadable/capped traversal -> scan notes | Limitations are surfaced without failing unrelated scanners. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | Candidate scanner | avoid | Scanner never writes, edits, validates, runs, or rewrites scripts; tests and grep verify no `Process`, `Data(contentsOf:)`, or full-content reads are added. |
| T-07-02 | Denial of Service | Candidate traversal | mitigate | Enforce default roots, max depth 2, max visited files 2,000, max results 200, size limit 1,000,000 bytes, and skip dependency/cache directories. |
| T-07-03 | Information Disclosure | Fixtures/docs | mitigate | Tests and docs use synthetic script names and avoid real local automation names, script contents, usernames beyond generic examples, tokens, or logs. |
| T-07-05 | Spoofing | Candidate evidence label | mitigate | Use `.candidate`, `state = "candidate"`, and `Script candidate (no schedule evidence)` for every candidate record. |
</threat_model>
