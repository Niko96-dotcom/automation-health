<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SwiftUI form -> `JobStore` | User-entered manual metadata enters the app through store methods, not direct view IO. |
| `JobStore` -> `ManualRecordStore` | The only write path is app-owned JSON in Application Support. |
| Manual JSON -> inventory model | Manual records are normalized as Manual confidence and never treated as scheduler evidence. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | Manual edit/remove UI | mitigate | Gate edit/remove actions by `job.job.source == .manualRecords`; no mutation controls are exposed for real scheduler, candidate, Shortcuts, Automator, cron, launchd, or Hermes records. |
| T-07-03 | Information Disclosure | Manual fixtures/docs | mitigate | Use synthetic names and paths such as `/Users/example/Scripts/archive.sh`; do not commit real notes, local job names, or private paths. |
| T-07-04 | Tampering | Manual JSON store | mitigate | Create parent directory, use atomic writes where practical, and never delete/overwrite malformed JSON during scan recovery. |
| T-07-05 | Spoofing | Manual UI affordances | mitigate | Use Manual confidence, explicit app-owned copy, and destructive confirmation text naming the systems that are not changed. |
</threat_model>
