<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Inventory model -> presentation | Source, confidence, origin, schedule, command/path, definition, and notes become UI search/detail text. |
| UI controls -> real automation sources | Candidate/manual UI must not create affordances that mutate real scheduler or script files. |
| User-facing copy -> expectations | Copy must distinguish app-owned Manual records and Candidate evidence limits from scheduled jobs. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | Detail actions | mitigate | Edit/remove controls are gated to `.manualRecords`; Candidate scripts get reveal-only behavior. |
| T-07-02 | Denial of Service | Search/detail integration | mitigate | Presentation uses existing bounded strings and scanner-provided snippets; no new recursive IO is introduced in views. |
| T-07-03 | Information Disclosure | UI/docs examples | mitigate | Manual verification uses synthetic examples; docs avoid real local automation names and script contents. |
| T-07-05 | Spoofing | Confidence/origin labels | mitigate | Sidebar/detail show confidence and origin as text; Candidate/Manual records use explicit no-schedule-evidence fallbacks. |
</threat_model>
