# Phase 03 - UI Design Contract

> Visual and interaction contract for the Sidebar Polish And Verification phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none - native macOS SwiftUI contract |
| Preset | not applicable |
| Component library | SwiftUI and AppKit native controls only |
| Icon library | SF Symbols through `Image(systemName:)` and `Label` |
| Font | macOS system font through SwiftUI semantic text styles |

No third-party UI package, shadcn preset, Tailwind configuration, registry block, or new dependency is used for this phase.

## Visual Hierarchy And Interaction

| Contract | Decision |
|----------|----------|
| Primary surface | Existing left sidebar inside `NavigationSplitView`, from the search field through the grouped job list and scan footer. |
| Focal point | The selected job row remains the primary visual anchor. Section headers organize scanning, and the filtered-empty state replaces the job list only when search hides every visible row. |
| Visual hierarchy | Sidebar summary is quiet metadata; source headers are compact structure; job rows are the only selectable navigation items; the selected row is the strongest visual cue. |
| Header format | Use a compact label-plus-count treatment: source label at the leading edge, visible count as subdued trailing text, and a subtle divider for group separation. Do not use parenthetical counts or count badges in Phase 3. |
| Header behavior | Source headers remain non-selectable, non-collapsible, and skipped by keyboard navigation. They do not receive click handlers, selection styling, hover styling, or focus state. |
| Row behavior | Preserve the current row structure: health dot, display name, subtitle, and soft selected-row background. Polish spacing and hover only; do not redesign rows. |
| Selected row | Preserve the current soft accent selected-row fill. Tuning opacity or corner radius is allowed only if the result stays quiet and source-list-like. |
| Hover state | Add a quiet hover background for unselected rows if it fits cleanly in `SidebarJobRow`. Hover must not compete with selected-row styling and must not add a custom focus ring. |
| Filtered empty state | When the trimmed search query is non-empty and `sections` has no jobs, show a small inline empty state in the sidebar list area. |
| Empty-state behavior | The empty state is not selectable, does not receive an id in the visible job order, and must not change Up/Down keyboard behavior when no visible jobs exist. |
| Search recovery | Clearing or changing search restores the normal grouped job list using existing filtering and navigation behavior. |
| Out of scope | No grouping mode picker, collapsible sections, custom preferences, type-ahead navigation, new keyboard shortcuts, job mutation controls, scanner changes, or full sidebar redesign. |

## Spacing Scale

Declared values for Phase 3 additions:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Header-to-divider gap, title-to-subtitle gap, compact inline gaps |
| sm | 8px | Sidebar edge padding, row horizontal padding, header horizontal padding, empty-state text gap |
| md | 16px | Source section separation, footer/action grouping, empty-state vertical inset |
| lg | 24px | Larger list-area breathing room only when replacing an empty filtered job list |
| xl | 32px | Reserved for page-level detail spacing outside this phase |
| 2xl | 48px | Reserved for major section breaks outside this phase |
| 3xl | 64px | Reserved for full-page layout spacing outside this phase |

Exceptions: none for new or tuned Phase 3 spacing. Preserve untouched existing layout values where outside the Phase 3 diff, but do not introduce new off-scale spacing.

## Typography

Use only these font sizes and weights for Phase 3 sidebar work:

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Section label | 11px | semibold (600) | 1.2 | Source names and visible counts in section headers |
| Row title | 13px | regular (400) | 1.35 | Job display names |
| Row detail | 12px | regular (400) | 1.3 | Job subtitles and empty-state body copy |
| Detail heading | 17px | semibold (600) | 1.2 | Existing detail/support headings only if touched |

Use exactly two weights in this phase: regular (400) and semibold (600). Keep sidebar row text single-line with truncation, not wrapping. Empty-state copy may wrap within the sidebar column if needed, but it should remain short.

## Color

Use semantic macOS colors and materials so the sidebar adapts to Light Mode, Dark Mode, and user accent color settings.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | macOS regular material; approx. #F5F5F7 light / #1E1E1E dark | Sidebar background and root list surface |
| Secondary (30%) | `Color.secondary`; approx. #6E6E73 light / #A1A1A6 dark | Section headers, counts, subtitles, footer metadata, empty-state body |
| Accent (10%) | `Color.accentColor`; selected background near current soft opacity | Selected job row background, native focus affordance if provided by SwiftUI, active sidebar affordance |
| Destructive | system red; approx. #FF3B30 light / #FF453A dark | Not used in Phase 3; reserved for future destructive warnings only |

Accent reserved for: selected job row background, native focus indication, and existing system-tinted chrome. Do not use accent color for every interactive element.

Semantic status colors remain separate from accent color:

| Status | Color |
|--------|-------|
| Healthy | system green |
| Waiting | system blue |
| Stale | system orange |
| Failed | system red |
| Unknown | system gray |

Status colors are reserved for the existing `HealthDot` and must not be repurposed as header, hover, selection, or empty-state decoration.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Rescan Jobs` if the toolbar refresh label is touched; Phase 3 adds no new CTA. |
| Section header | Leading source label plus trailing visible count, for example `launchd` and `3`; do not render `launchd (3)` in the polished header. |
| Row subtitle | Existing grouped subtitle behavior: next-run text when available; otherwise schedule text. Do not re-add source name. |
| Filtered empty state heading | `No matching automations` |
| Filtered empty state body | `Try a different search.` |
| Error state | `Could not scan automations. Review the scheduler files, then choose Rescan Jobs.` |
| Destructive confirmation | None. This phase adds no destructive actions and never mutates scheduled jobs. |

Do not add generic button labels such as `OK`, `Submit`, or `Cancel`. Do not add visible instructional shortcut text for Up/Down navigation.

## Implementation Contract For Planning

| Area | Contract |
|------|----------|
| Data boundary | Use `SidebarJobSection` and `SidebarJobSummary` values passed into `SidebarView`. Do not read scheduler files from views. |
| Search-empty signal | `ContentView` may pass a derived boolean such as `showsFilteredEmptyState`, based on a non-empty trimmed search query and no visible sidebar jobs. |
| Empty rendering | Render filtered empty state inside the list area where grouped rows would appear. It must not be part of `visibleJobs` and must not receive row selection behavior. |
| Navigation source | Continue using `sections.flatMap(\.jobs)` as the only Up/Down traversal source. When it is empty, keyboard navigation returns ignored and leaves selection unchanged. |
| Header polish | Update `SourceSectionHeader` to label-plus-count with subtle divider treatment while preserving source order and filtered visible counts. |
| Row polish | Keep `SidebarJobRow` as a plain button with health dot, title, subtitle, soft selected background, and existing selection binding. Hover polish must be local to row presentation. |
| Selection | Do not create parallel selected-row state. Preserve `selectedJobID` as the single selection binding. |
| Read-only boundary | Sidebar polish must not mutate scheduler files, job definitions, launchd state, Hermes cron metadata, or output files. |
| Verification | Plan must include `./script/ci.sh` plus a manual sidebar behavior check for row content, selection styling, no-results empty state, search clearing, and grouped Up/Down navigation. |
