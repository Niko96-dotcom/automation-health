**Method 1: `typeToSelectMatch` — First match for a prefix**

```swift
public static func typeToSelectMatch(for prefix: String, in sections: [SidebarJobSection]) -> String? {
    let lowercased = prefix.lowercased()
    guard !lowercased.isEmpty else { return nil }

    let allVisible = sections.flatMap(\.jobs)
    return allVisible.first { $0.displayName.lowercased().hasPrefix(lowercased) }?.id
}
```

Takes a prefix string (accumulated multi-character buffer). Returns the ID of the first visible job whose `displayName` has a case-insensitive prefix match. Returns `nil` if no match or empty prefix. Only searches `sections.flatMap(\.jobs)` (visible jobs — collapsed sections have empty `jobs` arrays, so collapsed jobs are automatically excluded per D-09 "only considers visible jobs").

**Method 2: `typeToSelectNextMatch` — Cycle to next match for a prefix**

```swift
public static func typeToSelectNextMatch(for prefix: String, in sections: [SidebarJobSection], after currentID: String) -> String? {
    let lowercased = prefix.lowercased()
    guard !lowercased.isEmpty else { return nil }

    let allVisible = sections.flatMap(\.jobs)
    let matchingIDs = allVisible
        .filter { $0.displayName.lowercased().hasPrefix(lowercased) }
        .map(\.id)

    guard !matchingIDs.isEmpty else { return nil }

    // Find current selection's position in matching list
    if let currentIndex = matchingIDs.firstIndex(of: currentID) {
        let nextIndex = currentIndex + 1
        if nextIndex < matchingIDs.endIndex {
            return matchingIDs[nextIndex]
        }
        // Wrap around: at end of matches, cycle back to first
        return matchingIDs.first
    }

    // Current selection not in matching list — return first match
    return matchingIDs.first
}
```

Cycles through all visible jobs matching the prefix. If `currentID` is among the matches, returns the next match (wrapping to first at end). If `currentID` is not among the matches, returns the first match. Returns `nil` if no visible jobs match or empty prefix.

These methods are pure functions (no state, no timer) — testable in self-test (Plan 03) without UI involvement.

**C. Add type-to-select .onKeyPress handler**

Add a new `.onKeyPress` handler to the ScrollView (the `.focusable()` view). Place it AFTER the existing arrow key handlers but BEFORE `.onChange(of: keyboardNavigationTargetID)`:

```swift
.onKeyPress(characters: .alphanumerics) { press in
    guard focusedTarget == .jobList else { return .ignored }
    guard let character = press.characters.first else { return .ignored }

    let now = Date()
    let elapsed = now.timeIntervalSince(typeSelectLastInput)

    // 300ms timeout: if too long since last input, reset the buffer
    if elapsed > 0.3 {
        typeSelectBuffer = ""
        typeSelectLastCharacter = nil
    }

    let isRepeat = (character == typeSelectLastCharacter)
    typeSelectLastInput = now
    typeSelectLastCharacter = character

    let targetID: String?

    if isRepeat && elapsed <= 0.3 {
        // Same character pressed within 300ms → cycle to next match (Finder-style)
        targetID = SidebarNavigation.typeToSelectNextMatch(
            for: typeSelectBuffer,
            in: sections,
            after: selectedJobID ?? ""
        )
    } else {
        // New character or buffer reset → extend buffer, find first match
        typeSelectBuffer.append(character)
        targetID = SidebarNavigation.typeToSelectMatch(
            for: typeSelectBuffer,
            in: sections
        )
    }

    guard let targetID else {
        // No match — silent no-op per D-10
        return .handled
    }

    keyboardNavigationTargetID = targetID
    selectedJobID = targetID
    return .handled
}
```

Key design:
- `.onKeyPress(characters: .alphanumerics)` only fires for letters and digits (a-z, A-Z, 0-9) — per UI-SPEC: "Any character key press (a-z, A-Z, 0-9, and symbols)". Note: `.alphanumerics` covers letters+digits; symbols like `-`, `_`, `.`, `/` won't be captured. Per D-10, this is acceptable — unmatched keys are silently ignored, and the primary use case is job name letters.
- Gate on `focusedTarget == .jobList` ensures type-to-select only works when job list has keyboard focus
- 300ms timeout resets the buffer (Date.distantPast ensures first-ever keypress triggers reset)
- Same-character cycle (Finder-style): if the same character is pressed within 300ms, cycle through matches rather than extending the buffer
- `keyboardNavigationTargetID` triggers the existing `.onChange` handler which calls `proxy.scrollTo`
- Returns `.handled` even on no-match to prevent key-press from falling through to other handlers

**Why `.onKeyPress(characters: .alphanumerics)` and not a plain `.onKeyPress`:** The character-specific modifier means arrow keys, Escape, modifiers, etc. pass through without interception. This guarantees coexistence with existing `.onKeyPress(.downArrow)` and `.onKeyPress(.upArrow)` handlers per success criterion #5.
