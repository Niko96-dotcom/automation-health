## Interaction Contract

### Keyboard Shortcuts — Global (CommandMenu)

These shortcuts are registered in `AutomationHealthApp` via `.commands` modifier. They are active regardless of which view has focus, as long as the app is frontmost.

| Shortcut | Keys | Action | Implementation Location |
|----------|------|--------|------------------------|
| Focus search field | `Cmd+Shift+F` | Sets `@FocusState isSearchFieldFocused = true` in ContentView. Search field receives key focus. Cursor appears in search field. Existing search text is selected (native NSSearchField behavior). | `AutomationHealthApp.commands` → `ContentView.@FocusState` |
| Expand all sections | `Cmd+Shift+E` | Sets `preferences.sidebarExpandAllOverride = true`. All sidebar sections animate open. Override persists until user manually clicks any disclosure triangle (which resets override to `nil`). | `AutomationHealthApp.commands` → `PreferencesStore.sidebarExpandAllOverride` |
| Collapse all sections | `Cmd+Shift+W` | Sets `preferences.sidebarExpandAllOverride = false`. All sidebar sections animate closed. Override persists until user manually clicks any disclosure triangle. | `AutomationHealthApp.commands` → `PreferencesStore.sidebarExpandAllOverride` |
| Group by Source | `Cmd+1` | Sets `preferences.groupingMode = .source`. Sidebar recomputes sections. Selection preserved if the selected job exists in new grouping. | `AutomationHealthApp.commands` → `PreferencesStore.groupingMode` |
| Group by Origin | `Cmd+2` | Sets `preferences.groupingMode = .origin`. | Same pattern |
| Group by Health | `Cmd+3` | Sets `preferences.groupingMode = .health`. | Same pattern |
| Group by Trigger | `Cmd+4` | Sets `preferences.groupingMode = .trigger`. | Same pattern |
| Group by Confidence | `Cmd+5` | Sets `preferences.groupingMode = .confidence`. | Same pattern |

### Keyboard Shortcuts — View-Local (onKeyPress)

These shortcuts are handled within `SidebarView` via `.onKeyPress`. They are active only when the sidebar job list has focus (`focusedTarget == .jobList`).

| Shortcut | Keys | Action |
|----------|------|--------|
| Move selection down | `↓` (Down Arrow) | Navigate to next visible job. Scroll to target via `ScrollViewReader`. Existing behavior — unchanged. |
| Move selection up | `↑` (Up Arrow) | Navigate to previous visible job. Scroll to target. Existing behavior — unchanged. |
| Escape | `⎋` (Escape) | Clears `searchText` (set to `""`) AND defocuses the search field (sets `isSearchFieldFocused = false`). Focus returns to the job list so arrow keys immediately resume working. |

### Keyboard Shortcut — Escape (ContentView)

Escape is handled in `ContentView` because it needs access to both `searchText` and `isSearchFieldFocused`.

| Shortcut | Keys | Action |
|----------|------|--------|
| Escape | `⎋` (Escape) | When search field is focused or has non-empty text: clears `searchText` to `""`, sets `isSearchFieldFocused = false`. If search field is already empty and unfocused, Escape passes through — job list arrow navigation continues to work. |

### Type-to-Select Behavior

| Property | Value |
|----------|-------|
| Trigger | Any character key press (a-z, A-Z, 0-9, and symbols) while sidebar job list has focus (`focusedTarget == .jobList`) |
| Buffer duration | 300ms timeout |
| Buffer behavior | Characters accumulate in a buffer. If the user pauses for 300ms, the buffer resets. If the user types within 300ms, the buffer extends and matching is performed against the accumulated string. |
| Matching | Match against `SidebarJobSummary.displayName` prefix, case-insensitive. Only considers **visible jobs** (respecting collapse state, grouping mode, and any search filter). |
| Selection | First matching job is selected (`selectedJobID = match.id`). The sidebar scrolls to the matching row via existing `ScrollViewReader` + `keyboardNavigationTargetID` pattern. |
| No match | Silent no-op. Current selection is unchanged. No visual feedback. No beep. |
| Repeat character | If the same character is pressed repeatedly within the buffer window, cycles through all matches for that character prefix (Finder-style behavior). |
| Modifier keys | Cmd, Shift, Option, Control, Fn key presses are **not** handled by type-to-select. They pass through for system shortcuts. |

**Implementation pattern:** Reuses existing `SidebarNavigation` helpers for job ID resolution. The buffer timer can use `DispatchQueue.main.asyncAfter` with cancellation or a Combine `PassthroughSubject` with `.debounce(for: .milliseconds(300), scheduler: DispatchQueue.main)`.

**Source:** Pre-populated from 11-CONTEXT.md D-04, D-09, D-10. The 300ms timeout follows macOS Finder convention.

## Focus Contract

### Focus States

| Focus State | Where Declared | Purpose |
|-------------|---------------|---------|
| `searchFieldFocused: Bool` | `ContentView` | Controls whether the `.searchable` field has keyboard focus. Set to `true` by Cmd+Shift+F shortcut. Set to `false` by Escape or user clicking outside. |
| `focusedTarget: SidebarFocusTarget?` | `SidebarView` | Controls whether the job list has keyboard focus (`.jobList`). This is the existing focus state — unchanged. |

### Focus Ring Visual Contract

| Element | Focus Indicator | When Visible |
|---------|----------------|-------------|
| Sidebar job list | `RoundedRectangle(cornerRadius: 8)` with `.strokeBorder(Color.accentColor.opacity(0.9), lineWidth: 2)` | When `focusedTarget == .jobList` (existing behavior, unchanged) |
| Search field | Native `NSSearchField` focus ring (system-defined blue glow on focus) | When `searchFieldFocused == true` |

### Focus Transitions

```
State: Job list focused (focusedTarget == .jobList)
  ├── User presses Cmd+Shift+F
  │   → searchFieldFocused = true
  │   → Native focus moves to search field
  │   → Focus ring moves from job list to search field
  │
  ├── User presses Up/Down Arrow
  │   → Navigate selection within job list (unchanged)
  │
  └── User types a-z (type-to-select)
      → Buffer character, attempt match, scroll+select if found

State: Search field focused (searchFieldFocused == true)
  ├── User presses Escape
  │   → searchText = ""
  │   → searchFieldFocused = false
  │   → Focus returns to job list (focusedTarget = .jobList)
  │   → Job list focus ring appears
  │
  ├── User presses Enter/Return
  │   → Standard search behavior (filter sidebar, no focus change)
  │
  └── User clicks a sidebar job row
      → Selection changes, search field may lose focus (standard SwiftUI behavior)
```

### Expand/Collapse Override State

| Property | Type | Location | Behavior |
|----------|------|----------|----------|
| `sidebarExpandAllOverride` | `Bool?` | `PreferencesStore` (new `@Published` property) | `nil` = no override (normal collapse state applies). `true` = all sections forced open. `false` = all sections forced closed. Reset to `nil` when user manually clicks any disclosure triangle. |

**Override lifecycle:**
1. User presses Cmd+Shift+E → `sidebarExpandAllOverride = true` → all sections expand
2. Sidebar renders with all sections open, regardless of `collapseState`
3. User clicks a section disclosure triangle → `sidebarExpandAllOverride` resets to `nil` → normal collapse state resumes for that click onward
4. Same for Cmd+Shift+W → `sidebarExpandAllOverride = false` → all sections collapse → manual click resets

**Source:** Pre-populated from 11-CONTEXT.md D-06, D-08, D-12.

**Key interaction zones:**
1. **Menu bar (View menu):** Cmd+Shift+E, Cmd+Shift+W, Cmd+Shift+F, Cmd+1 through Cmd+5 — all global, always available

3. **Job list:** Focused by default after Escape. Arrow keys navigate. Type-to-select (300ms buffer) matches and scrolls. Blue accent focus ring when focused.
