<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `/usr/bin/crontab -l` -> scanner parser | Production command output is treated as untrusted text and parsed read-only. |
| System cron files -> scanner parser | Readable file contents are parsed without writing back to cron locations. |
| Cron limitations -> scan notes | Missing, protected, or unavailable sources become user-visible notes instead of fatal failures. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-02-01 | Tampering | Cron command runner | avoid | Production runner invokes only `/usr/bin/crontab -l`; grep verifies no `-e` or `-r` usage. |
| T-06-02-02 | Information Disclosure | Cron fixtures/docs | mitigate | Use synthetic commands and paths under `/Users/example`; do not commit real crontab output. |
| T-06-02-03 | Denial of Service | Cron parser | mitigate | Parse bounded strings/files from injected sources and skip comments/env lines without recursive filesystem traversal. |
| T-06-02-04 | Spoofing | Cron origin classification | mitigate | Use `.userAuthored` only for current-user crontab and `.system` only for explicit system files; otherwise prefer `.unknown`. |
| T-06-02-05 | Elevation of Privilege | Protected cron files | avoid | Do not require root access; unreadable/protected files produce scan notes. |
</threat_model>
