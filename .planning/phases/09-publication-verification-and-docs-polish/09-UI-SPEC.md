# Phase 09 - UI Design Contract

> Visual and interaction contract for publication verification, sanitized public visuals, and final docs polish. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase Boundary

Phase 9 prepares Automation Health for public release by validating privacy safety, public visuals, final regression behavior, and traceability evidence. It should make the existing app and docs feel clean, credible, and publication-ready without adding new scheduler capabilities.

In scope:

- Refresh README and docs visual references so they use sanitized abstract assets or explicitly synthetic screenshots only.
- Keep public visuals aesthetically aligned with the current Pulse Grid app icon identity.
- Define how any verification notes, scrub results, and publication evidence should be presented in docs and planning summaries.
- Preserve the existing native macOS app visual language when screenshots are captured or referenced.
- Confirm final manual verification covers broad inventory, manual records, sidebar grouping/collapse, focus styling, search, selection, refresh, and read-only posture.

Out of scope:

- Redesigning the SwiftUI app shell, sidebar, detail view, manual record flows, or scanner presentation.
- Adding marketing landing pages, decorative hero layouts, screenshots from real local automation data, or raw terminal-output images.
- Adding job mutation controls, scheduler repair actions, run buttons, or any write behavior for real scheduled jobs.
- Adding new third-party packages, web component systems, shadcn, Tailwind, or design registries.
- Signed/notarized distribution; future distribution work owns that path.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | Native SwiftUI/AppKit only |
| Icon library | SF Symbols for app UI; committed bitmap PNG/ICNS for app icon assets |
| Font | macOS system font, SF Pro |

Design system notes:

- No React, Tailwind, shadcn, or web registry is present.
- Public docs should use Markdown, repository screenshots only when synthetic, and existing app/icon assets instead of introducing a separate visual system.
- Any captured app screenshot must show synthetic automation records, synthetic paths, and synthetic output only.
- Keep the current app surface intact: `NavigationSplitView`, `.searchable`, native toolbar buttons, compact sidebar rows, section disclosure controls, material cards, and SF Symbol labels.
- Do not introduce large cards, decorative page sections, oversized headers, gradient backgrounds, or marketing-style compositions for docs visuals.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline icon/text gaps, small checklist status spacing |
| sm | 8px | Compact metadata rows, scrub-result table rhythm, screenshot caption spacing |
| md | 16px | Default docs section spacing, app screenshot margins, verification checklist groups |
| lg | 24px | Major README/docs visual blocks and publication evidence sections |
| xl | 32px | Separation before final publication summary or screenshot groups |
| 2xl | 48px | Reserved for wide docs visual previews only |
| 3xl | 64px | Not used in Phase 9 app or docs polish |

Exceptions: Native macOS control intrinsic sizes, SF Symbol drawing metrics, image pixel dimensions, app icon export sizes, and 1-2px screenshot or focus strokes are platform/asset metrics rather than spacing tokens.

Implementation constraints:

- Public docs screenshots should be cropped with enough 16px or 24px breathing room to show context, but never include private menu bar, desktop, filesystem, username, hostname, or real job data.
- Screenshot captions and verification notes should remain compact; avoid long prose immediately under images.
- App screenshot contents must preserve Phase 8 compact sidebar spacing and current detail-card density.

## Typography

Use exactly these type roles for Phase 9 docs visuals, generated verification notes, and any screenshot captioning. The app UI continues to use native SwiftUI type styles that map to these roles.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 600 | 1.3 |
| Body | 14px | 400 | 1.5 |
| Heading | 18px | 600 | 1.25 |
| Display | 24px | 600 | 1.2 |

Typography constraints:

- Allowed weights: 400 regular and 600 semibold only.
- Use monospaced system text only for commands, file paths, fixture snippets, and scrub-result examples.
- Public docs should not include decorative display type, image text overlays, terminal screenshots, or screenshot annotations.
- Sidebar screenshots must keep row text at Label/Body scale; no hero-sized sidebar text or marketing labels.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F5F5F2` light / `#1D1D1F` dark | README/docs background context, app window background, broad native surfaces |
| Secondary (30%) | `#E8E8E3` light / `#2A2A2D` dark | Sidebar material, verification note surfaces, table/caption backgrounds when needed |
| Accent (10%) | `#32D583` | Existing health pulse identity, selected sidebar row, approved verification status, custom focus cue |
| Destructive | `#D92D20` | Failed scrub findings, failed CI/manual checks, and destructive manual-record UI already present |

Accent reserved for: the app health pulse identity, approved verification status markers, selected sidebar row treatment, active grouping indicator, and custom focus stroke. Do not use accent for all links, every checklist item, broad docs backgrounds, screenshot frames, private-data warnings, or decorative fills.

Color constraints:

- Public visual assets should align with the current Pulse Grid icon direction: off-white/light gray tile, black/graphite glyph, quiet material depth, and only restrained health-accent usage.
- Existing semantic health colors remain unchanged: green for alive, blue for waiting, orange for stale, red for needs attention, and gray for unknown.
- Privacy and CI failure states use destructive red only when a check fails; warning copy may use native warning styling or orange text sparingly.
- Screenshots must remain legible in light and dark mode where captured; do not rely on color alone to communicate verification status.

## Visual Hierarchy

Primary focal point:

- Public docs and release notes: the clean publication status and sanitized app identity are the visual anchors, not raw scan data or terminal output.

Secondary focal points:

- Sanitized abstract Pulse Grid icon asset.
- Synthetic sidebar/detail screenshot, if one is added.
- Privacy scrub status table or checklist.
- CI/manual verification status summary.
- Requirement traceability for `PRIV-01`, `VIS-04`, and `QUAL-04`.

Icon and visual mapping:

| Element | Visual / SF Symbol | Treatment |
|---------|--------------------|-----------|
| App identity | `Assets/AppIcon/automation-health-icon-source.png` or generated ICNS | Abstract Pulse Grid asset only; no text or real scheduler data |
| Privacy scrub | `lock.shield` | Label-only status row in docs or app screenshot notes |
| CI verification | `checkmark.seal` | Approved status only after commands pass |
| Manual smoke check | `checklist` | Checklist or table row, not a decorative badge wall |
| Public visual safety | `photo.on.rectangle.angled` | Used only for sanitized visual evidence |
| Failed check | `exclamationmark.triangle` | Paired with exact remediation text |

Visual constraints:

- If screenshots are used, they must show synthetic automation names such as `example-daily-report`, `sample-backup-check`, or `demo-shortcut-sync`.
- Screenshot content must replace real paths with `/Users/example/...`, hostnames with `example-mac`, and output with synthetic summaries.
- Do not include raw logs, terminal screenshots, private prompts, local filesystem sidebars, desktop wallpaper, menu bar identity, or real automation output.
- If the README does not need screenshots, use the abstract icon asset and explicit visual safety notes instead of forcing a screenshot.

## Public Visual Asset Contract

Accepted public visuals:

| Visual Type | Contract |
|-------------|----------|
| App icon source art | Use committed abstract Pulse Grid PNG/ICNS assets only |
| README identity image | Use app icon or a small sanitized app visual; no real local automation rows |
| App screenshot | Synthetic data only; no real scheduler definitions, paths, output, hostnames, usernames, tokens, or job names |
| Verification evidence | Tables, checklists, and command names as text; no raw terminal screenshots |
| Release notes visual | Reuse sanitized icon/app screenshot; do not create a separate marketing graphic |

Screenshot requirements, if screenshots are added:

- Capture from a clean local state using synthetic fixture/manual records only.
- Show at least one sidebar grouping state and one detail surface only if all visible data is synthetic.
- Keep the app chrome native and compact; do not crop so tightly that the sidebar/detail relationship is unclear.
- Run privacy scrub commands after adding or replacing any image.
- Add alt text that describes the visual without exposing private data.

## Interaction Contract

Phase 9 adds no new in-app control surface by default. Any docs command, checklist action, or verification step introduced by this phase must use explicit text labels and preserve read-only behavior.

| Interaction | Contract |
|-------------|----------|
| Run privacy scrub | Command label: `Run Publication Scrub`; use commands from `docs/privacy-scrub-checklist.md` |
| Verify app icon | Command label: `Verify App Icon`; use `./script/test_app_icon.sh` or `./script/test_app_icon.sh --bundle` where applicable |
| Run CI | Command label: `Run Local CI`; use `./script/ci.sh` |
| Verify app bundle | Command label: `Verify App Bundle`; use `./script/build_and_run.sh --verify` |
| Record manual smoke results | Command label: `Record Publication Smoke Check`; summarize pass/fail evidence in Phase 9 docs |
| Resolve scrub failure | Provide exact file/path and remediation; do not hide failed checks behind generic status copy |
| Destructive actions | None introduced in the app; deleting accidental `.DS_Store` metadata is repository cleanup, not app UI behavior |

Read-only constraints:

- Manual verification must explicitly confirm the app does not edit real scheduler files, scripts, Shortcuts, Automator workflows, cron entries, launchd plists, or Hermes metadata.
- Docs must not describe job management, repair, run-now, delete, or scheduler-edit workflows as available.
- Any Finder reveal or manual-record removal behavior mentioned must retain existing labels and safety wording.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Run Publication Scrub |
| Empty state heading | Publication evidence needed |
| Empty state body | Run the privacy scrub, icon validation, local CI, app bundle verification, and manual smoke checks before marking Phase 9 complete. |
| Error state | Publication check failed. Resolve the listed file or command finding, rerun the check, and record the passing evidence before publishing. |
| Destructive confirmation | None - this phase adds no destructive app actions. Repository cleanup may remove accidental `.DS_Store` metadata after review. |

Required status copy:

| Status | Copy |
|--------|------|
| Scrub pass | Privacy scrub passed with no unexpected public-surface findings. |
| Scrub false positive | Expected checklist guidance match; no private data is published. |
| Scrub fail | Unexpected privacy finding remains in `{path}`. Replace it with sanitized content before publishing. |
| Visual pass | Public visuals use abstract or synthetic data only. |
| Visual fail | Public visual contains private or machine-specific data and must be replaced. |
| CI pass | Local CI passed with public docs, scanners, icon assets, manual records, and sidebar changes. |
| Manual pass | Manual smoke check passed for search, selection, refresh, manual records, grouping, collapse, focus, and read-only behavior. |

Copy tone:

- Direct, local, and evidence-based.
- Prefer "public visuals", "synthetic data", "publication scrub", "manual smoke check", and "read-only inventory".
- Avoid launch-day hype, marketing claims, and promises that every automation on every Mac will be discovered.
- Never include real scheduler output, job names, usernames, hostnames, personal paths, tokens, secrets, screenshots, or private command output in public docs.

## Manual Verification Surface

Manual verification notes should use a compact checklist or table with one row per behavior:

| Area | Required Evidence |
|------|-------------------|
| Privacy scrub | Commands from `docs/privacy-scrub-checklist.md` have no unexpected hits |
| Public visuals | README/docs use icon assets or synthetic screenshots only |
| Launchd and Hermes cron | Existing records still render where privacy-safe local data is available |
| Broad inventory | cron, Shortcuts, Automator, candidate, and manual records remain searchable/selectable where fixtures or safe local records exist |
| Manual records | Add, edit, and remove app-only records without modifying real scheduler files |
| Sidebar grouping | Source, Origin, Health, Trigger, and Confidence grouping remain stable |
| Collapse/search | Collapsed groups preserve selection; search reveals matching rows without mutating collapse state |
| Focus styling | Custom focus cue is visible and the oversized default blue rectangle is absent |
| Refresh | Rescan keeps selection where possible and reports scan notes without crashing |
| Read-only posture | No real automation mutation controls are introduced |

Formatting constraints:

- Keep evidence summaries short enough to scan in a release checklist.
- Use command names and pass/fail outcomes, not pasted full terminal logs.
- Use exact requirement IDs `PRIV-01`, `VIS-04`, and `QUAL-04` in final traceability notes.
