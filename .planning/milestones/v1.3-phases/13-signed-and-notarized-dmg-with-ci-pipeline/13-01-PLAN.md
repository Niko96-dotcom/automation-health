  <action>
Create the file `entitlements/release.entitlements` (creating the `entitlements/` directory if it does not exist) with this exact content:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>com.apple.security.get-task-allow</key>
    <false/>
</dict>
</plist>
```

The single entitlement `com.apple.security.get-task-allow` set to `false` prevents debugger attachment, which is required by Apple for notarization of distribution builds. The hardened runtime itself is activated by the `--options runtime` codesign flag (set in the release script), not by this entitlements file.

No additional entitlements are needed because the app does not use the App Sandbox — file access is unrestricted, and `Process("/bin/launchctl")` works under hardened runtime without special entitlements (hardened runtime allows `posix_spawn`/`NSTask` of system binaries).

<task type="auto" tdd="false">
  <name>Task 2: Create release script with build, codesign, DMG, notarize, and staple steps</name>
  <files>script/release.sh</files>
  <read_first>script/build_and_run.sh, entitlements/release.entitlements, Package.swift</read_first>
  <action>
Create `script/release.sh` with `#!/usr/bin/env bash` and `set -euo pipefail`. The script must be self-contained — a single invocation with environment variable credentials produces the final DMG.

**Constants** (replicate from build_and_run.sh for independence):
- `APP_NAME="AutomationHealth"`
- `DISPLAY_NAME="Automation Health"`
- `BUNDLE_ID="org.automationhealth.AutomationHealth"`
- `MIN_SYSTEM_VERSION="14.0"`
- `ICON_NAME="AutomationHealth"`
- `VERSION="${GITHUB_REF_NAME:-$(git describe --tags --always --dirty)}"` — read version from git tag or commit

**Step 1 — Validate credentials (fail early with actionable messages):**
Check each required environment variable and exit with a clear message if missing:
- `$APPLE_DEVELOPER_IDENTITY` (e.g., "Developer ID Application: Your Name (XXXXXXXXXX)")
- `$APPLE_DEVELOPER_TEAM_ID` (10-char alphanumeric)
- `$APPLE_NOTARY_KEY_ID` (App Store Connect API Key ID)
- `$APPLE_NOTARY_KEY_FILE` (path to downloaded .p8 private key)
- `$APPLE_NOTARY_KEY_ISSUER_ID` (App Store Connect Issuer ID)
- `$GITHUB_TOKEN` (optional — skip GitHub Release upload if missing, print warning)

Exit code 1 with message "Error: APPLE_DEVELOPER_IDENTITY is not set. Set it to your Developer ID Application certificate common name." (and similarly for each) if any required var is missing.

**Step 2 — Build the release binary:**
```bash
swift build --configuration release
BINARY_PATH="$(swift build --configuration release --show-bin-path)/$APP_NAME"
```

**Step 3 — Assemble .app bundle in a staging directory:**
```bash
STAGING="$ROOT_DIR/.release-staging"
rm -rf "$STAGING"
mkdir -p "$STAGING/package"
APP_BUNDLE="$STAGING/package/$APP_NAME.app"
CONTENTS="$APP_BUNDLE/Contents"
MACOS_DIR="$CONTENTS/MacOS"
RESOURCES_DIR="$CONTENTS/Resources"

mkdir -p "$MACOS_DIR" "$RESOURCES_DIR"
cp "$BINARY_PATH" "$MACOS_DIR/$APP_NAME"
chmod +x "$MACOS_DIR/$APP_NAME"
```

**Step 3b — Copy icon:**
Use the same icon generation logic as build_and_run.sh: if `Assets/AppIcon/$ICON_NAME.icns` is missing or stale relative to `Assets/AppIcon/automation-health-icon-source.png` or `script/generate_app_icon.sh`, run `script/generate_app_icon.sh`. Then copy `Assets/AppIcon/$ICON_NAME.icns` to `$RESOURCES_DIR/$ICON_NAME.icns`.

**Step 3c — Write Info.plist:**
Write the same Info.plist as build_and_run.sh into `$CONTENTS/Info.plist` with these keys:
- CFBundleExecutable: $APP_NAME
- CFBundleIdentifier: $BUNDLE_ID (org.automationhealth.AutomationHealth)
- CFBundleName: $DISPLAY_NAME
- CFBundleDisplayName: $DISPLAY_NAME
- CFBundleIconFile: $ICON_NAME.icns
- CFBundlePackageType: APPL
- LSMinimumSystemVersion: $MIN_SYSTEM_VERSION
- NSPrincipalClass: NSApplication
- CFBundleShortVersionString: $VERSION (the git-derived version)
- CFBundleVersion: $VERSION

**Step 4 — Codesign the .app bundle with hardened runtime:**
```bash
codesign --deep --force --verify --verbose \
  --sign "$APPLE_DEVELOPER_IDENTITY" \
  --options runtime \
  --entitlements "$ROOT_DIR/entitlements/release.entitlements" \
  --timestamp \
  "$APP_BUNDLE"
```

Verify the signature was applied:
```bash
codesign --verify --verbose "$APP_BUNDLE"
```

**Step 5 — Create DMG with drag-to-install layout:**
First, create a temporary uncompressed DMG, mount it, arrange the layout, then convert to compressed read-only:
```bash
DMG_PATH="$ROOT_DIR/dist/$APP_NAME-$VERSION.dmg"
mkdir -p "$ROOT_DIR/dist"
TMP_DMG="$STAGING/tmp.dmg"

hdiutil create -size 150m -volname "$DISPLAY_NAME" -fs HFS+ -attach "$TMP_DMG"

# Copy app and create Applications symlink
cp -R "$APP_BUNDLE" "/Volumes/$DISPLAY_NAME/"
ln -s /Applications "/Volumes/$DISPLAY_NAME/Applications"

# Arrange icons using AppleScript
osascript <<END_SCRIPT
tell application "Finder"
  tell disk "$DISPLAY_NAME"
    open
    set current view of container window to icon view
    set toolbar visible of container window to false
    set statusbar visible of container window to false
    set the bounds of container window to {400, 200, 920, 520}
    set viewOptions to the icon view options of container window
    set arrangement of viewOptions to not arranged
    set icon size of viewOptions to 72
    set position of item "$APP_NAME.app" of container window to {160, 140}
    set position of item "Applications" of container window to {360, 140}
    update without registering applications
    close
  end tell
end tell
END_SCRIPT

# Detach and convert to compressed read-only
DISK_ID="$(hdiutil info | grep "/Volumes/$DISPLAY_NAME" | awk '{print $1}')"
hdiutil detach "$DISK_ID" -force
hdiutil convert "$TMP_DMG" -format UDZO -imagekey zlib-level=9 -o "$DMG_PATH"
rm -f "$TMP_DMG"
```

**Step 6 — Codesign the DMG:**
```bash
codesign --force --sign "$APPLE_DEVELOPER_IDENTITY" --timestamp "$DMG_PATH"
codesign --verify --verbose "$DMG_PATH"
```

**Step 7 — Submit for notarization using App Store Connect API key:**
```bash
xcrun notarytool submit "$DMG_PATH" \
  --key "$APPLE_NOTARY_KEY_FILE" \
  --key-id "$APPLE_NOTARY_KEY_ID" \
  --issuer "$APPLE_NOTARY_KEY_ISSUER_ID" \
  --wait \
  --output-format json \
  | tee "$STAGING/notary-result.json"
```

Check the notarization status. If `status` in the JSON output is not "Accepted", print the error details and exit with code 1.

**Step 8 — Log the notary submission ID:**
Extract the submission ID from the JSON output and run:
```bash
SUBMISSION_ID="$(jq -r '.id' "$STAGING/notary-result.json")"
xcrun notarytool log "$SUBMISSION_ID" \
  --key "$APPLE_NOTARY_KEY_FILE" \
  --key-id "$APPLE_NOTARY_KEY_ID" \
  --issuer "$APPLE_NOTARY_KEY_ISSUER_ID" \
  "$STAGING/notary-log.json"
```
Print the notarization status and issues (if any).

**Step 9 — Staple the notarization ticket to the DMG:**
```bash
xcrun stapler staple "$DMG_PATH"
```

**Step 10 — Verify the stapled DMG:**
```bash
xcrun stapler validate "$DMG_PATH"
spctl --assess --verbose --type install "$DMG_PATH" || echo "Warning: spctl assessment requires a non-development Mac or cleared assessment history"
```

**Step 11 — Print success summary:**
Print the DMG path, version, file size (`ls -lh "$DMG_PATH"`), and confirmation message:
```
=== Release Complete ===
DMG: dist/AutomationHealth-{version}.dmg
Size: {size}
Notarization: Accepted and stapled
Gatekeeper assessment: passed (if available)
```

The script must be at least 120 lines and handle errors at each step. Use `echo "=== Step N: Description ==="` before each major step for readability.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Developer machine -> Apple notary service | API key-based credentials sent over HTTPS to Apple's notary service via notarytool |
| CI runner -> Apple notary service | API key stored as GitHub Actions secret, used by notarytool in CI workflow |
| DMG hosted on GitHub Releases -> Downloading user | User downloads signed+notarized DMG, macOS Gatekeeper verifies signature and notarization |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-01 | Spoofing | script/release.sh — codesign identity | mitigate | The `$APPLE_DEVELOPER_IDENTITY` env var is validated before any codesigning — script exits with clear message if unset. Only a Developer ID Application certificate from Apple's certificate authority produces a valid signature. |
| T-13-02 | Tampering | script/release.sh — notarization bypass | mitigate | Script checks notarization result JSON for status="Accepted" before proceeding to stapling. If notarization fails or is skipped, the DMG is not stapled. |
| T-13-03 | Information Disclosure | script/release.sh — API key | mitigate | The notary API key file path is read from `$APPLE_NOTARY_KEY_FILE` env var; the key content is never echoed or logged. CI stores it as a masked GitHub Actions secret. |
| T-13-04 | Elevation of Privilege | entitlement — com.apple.security.get-task-allow | mitigate | Set to false — prevents debugger attachment to the signed distribution app. This is not a privilege escalation risk but a defense-in-depth measure required for notarization. |
| T-13-05 | Repudiation | Notarization audit log | accept | The notarytool submission produces an audit log stored in `.release-staging/notary-log.json`. Not signing the log is acceptable — integrity is provided by Apple's notary service records. |
| T-13-06 | Denial of Service | Notary service availability | accept | If Apple's notary service is unavailable, the release pipeline fails (notarytool times out or returns error). No mitigation needed — Apple's notary service is a hard dependency for distribution. |
</threat_model>
