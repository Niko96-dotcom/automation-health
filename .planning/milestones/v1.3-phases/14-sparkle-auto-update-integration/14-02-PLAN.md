7. **Add AppUpdaterDelegate class:** Add a file-private class at the bottom of the file (before the closing brace of the file, but outside `AutomationHealthApp` struct). This delegate provides the appcast feed URL:

```swift
// MARK: - Sparkle Updater Delegate

private final class AppUpdaterDelegate: NSObject, SPUUpdaterDelegate {
    func feedURLString(for updater: SPUUpdater) -> String? {
        // Use GitHub Releases appcast. The actual appcast.xml is generated by
        // the release pipeline (plan 14-03) and uploaded alongside the DMG.
        // For development builds without a real appcast, returning nil falls
        // back to Info.plist SUFeedURL — if both are absent, Sparkle will
        // fail gracefully (no updates found).
        guard let info = Bundle.main.infoDictionary,
              let version = info["CFBundleShortVersionString"] as? String,
              !version.hasSuffix("-dev"),
              !version.contains("0.0.0") else {
            return nil
        }
        // Appcast URL pattern: https://github.com/nikomohr/AutomationHealth/releases/download/v{version}/appcast.xml
        // Plan 14-03 will generate this file and upload it with the release.
        return "https://github.com/nikomohr/AutomationHealth/releases/download/v\(version)/appcast.xml"
    }

    func updater(_ updater: SPUUpdater, didFindValidUpdate item: SUAppcastItem) {
        // Update found — handled by Sparkle's standard UI
    }

    func updaterDidNotFindUpdate(_ updater: SPUUpdater, error: Error) {
        // No update available (normal case) — silent
    }

    func updater(_ updater: SPUUpdater, didAbortWithError error: Error) {
        // Update driver aborted — log for debugging
        NSLog("[Sparkle] Update driver aborted: \(error.localizedDescription)")
    }
}
```

**Important constraints:**
- The `feedURLString(for:)` implementation uses the actual GitHub username `nikomohr` and repo `AutomationHealth` — this is the project's confirmed GitHub repository
- The feedURL is only returned for non-dev versions (not `-dev` suffix, not `0.0.0`) because dev builds have no corresponding appcast to check against
- The delegate class is `fileprivate` — it is an implementation detail of the app entry point, not exported
- The SPUStandardUserDriver delegate is `nil` — we accept Sparkle's default gentle update behavior
- The updater is NOT started in init() — it is started in the `.task` modifier on the WindowGroup

```swift
Section("Updates") {
    if case .error(let message) = updateStore.updateState {
        // Error state — Sparkle could not initialize
        LabeledContent("Update checking is unavailable") {
            Text("Unavailable")
                .foregroundStyle(.secondary)
        }
        Text(message)
            .font(.caption)
            .foregroundStyle(.secondary)
    } else {
        // Normal state — Sparkle is working
        LabeledContent("Current Version") {
            if case .checking = updateStore.updateState {
                HStack(spacing: 4) {
                    ProgressView()
                        .scaleEffect(0.7)
                        .frame(width: 16, height: 16)
                    Text(updateStore.currentVersion)
                }
            } else {
                Text(updateStore.currentVersion)
            }
        }

        Toggle("Automatically check for updates", isOn: Binding(
            get: { updateStore.automaticallyChecksForUpdates },
            set: { updateStore.setAutomaticallyChecksForUpdates($0) }
        ))

        Button("Check for Updates") {
            updateStore.checkForUpdates()
        }
        .disabled(!updateStore.canCheckForUpdates || updateStore.updateState == .checking)
    }
}
```

| Error (.error) | "Update checking is unavailable" + error message | Not rendered | Not rendered |

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User -> Settings UI | User can toggle auto-checks and trigger manual checks — no privilege escalation beyond app scope |
| Appcast (GitHub Releases) -> Sparkle | HTTPS with EdDSA signature verification — tampering requires compromising either GitHub or the EdDSA private key |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-06 | Spoofing | `feedURLString(for:)` in AppUpdaterDelegate | mitigate | Only returns a URL for non-dev versions; the URL template points to GitHub Releases under the project's domain; EdDSA signature verification prevents spoofed appcasts from being accepted |
| T-14-07 | Denial of Service | `SettingsView` Updates section | mitigate | Error state (`.error`) renders gracefully — shows "Update checking is unavailable" with the error message; the rest of SettingsView continues to function; the app continues to function normally without updates |
| T-14-08 | Information Disclosure | Version string displayed in Settings | accept | Version string (`CFBundleShortVersionString`) is already public in the app bundle Info.plist and on GitHub Releases — no additional privacy risk |
| T-14-09 | Tampering | Menu item "Check for Updates" | mitigate | Disabled (`canCheckForUpdates` gate) when Sparkle is in an error state or a session is in progress; duplicate check requests are prevented |
| T-14-10 | Elevation of Privilege | Sparkle update installation | mitigate | Sparkle's standard install-and-relaunch flow runs under the user's own privileges — no privilege boundary is crossed; hardened runtime + EdDSA signature verification prevent unsigned code execution |
</threat_model>
